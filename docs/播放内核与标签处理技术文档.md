## 1. 总体架构

MusicTagRecover 由两大核心子系统构成，二者相互独立、仅通过 UI 层交互：

```
┌────────────────────────────────────────────────────────────┐
│                        WPF UI 层                            │
│   MainWindow / PlayerBar / TagEditControl / CompareWindow   │
└──────────────┬─────────────────────────────┬───────────────┘
               │                             │
┌──────────────▼──────────────┐  ┌───────────▼───────────────┐
│        播放子系统             │  │        标签子系统           │
│  Services/Playback/         │  │  Services/                 │
│  ┌────────────────────────┐ │  │  ┌──────────────────────┐ │
│  │ PreviewPlayerEngine    │ │  │  │ TagService           │ │
│  │ (调度/输出/同步)        │ │  │  │ (统一门面)            │ │
│  └───────┬───────┬────────┘ │  │  └──────┬───────────────┘ │
│          │       │          │  │         │                  │
│  ┌───────▼──┐ ┌──▼────────┐ │  │  ┌──────▼───────────────┐ │
│  │ApeDecoder│ │FfmpegDec. │ │  │  │TagLibSharp2Engine    │ │
│  │(官方SDK) │ │(FFmpeg 9) │ │  │  │(音频读写)             │ │
│  └──────────┘ └───────────┘ │  │  │MediaInfo(视频读)      │ │
│  NAudio WASAPI 输出          │  │  │TagLib 2.3(兜底)      │ │
└──────────────────────────────┘  └──┴──────────────────────┴─┘
```

- **播放子系统**：自研内核，解码与输出完全自控，不依赖 FFME/系统解码器。
- **标签子系统**：双轨制——音频标签读写走 TagLibSharp2 0.6.0，视频标签读走 MediaInfo 26.1.0，视频写与特殊格式走 TagLib(Sharp) 2.3.0 兜底。

## 2. 播放内核

### 2.1 架构设计与数据流

代码位置：`Services/Playback/`

| 文件 | 职责 |
|---|---|
| `IPreviewDecoder.cs` | 解码器抽象接口 |
| `PlaybackTypes.cs` | `PlaybackException` / `DecodedUnit` / `PlaybackBufferPool` |
| `FfmpegDecoder.cs` | FFmpeg.AutoGen 9 通用解码器（除 APE 外全部格式） |
| `ApeDecoder.cs` | Monkey's Audio 官方 SDK 专用解码器（.ape） |
| `PreviewPlayerEngine.cs` | 播放引擎：调度、输出、A/V 同步、播放控制 |

**数据流（音频）**：

```
文件 → [解码器] float32 交错 PCM 块（Pts 标记）
     → 解码线程水位控制（缓冲 <2s 才喂数据）
     → BufferedWaveProvider（5s 环形缓冲）
     → WaveOut (WASAPI, 150ms×3 缓冲) → 扬声器
```

**数据流（视频）**：

```
文件 → [解码器] BGRA32 帧（Pts 标记）
     → 有界队列（容量 4，满则解码线程等待）
     → UI 线程 DispatcherTimer(40ms) 调 PumpDueVideoFrame
     → 按播放时钟取到期帧 → WriteableBitmap.WritePixels → Image 控件
```

**格式分发**（`PreviewPlayerEngine.Open`）：

- `.ape` → `ApeDecoder`（官方 SDK，解决 FFmpeg 解码 APE 的卡顿/爆音问题）
- 其它全部 → `FfmpegDecoder`（FLAC/MP3/WAV/OGG/AAC/M4A/MP4/MKV/AVI/WMV/MOV/TS 等）

**统一输出约定**：

- 音频：float32 交错 PCM，保持源采样率；声道数 >2 时压成立体声。
- 视频：BGRA32 位图，`Stride = Width × 4`。

### 2.2 线程模型

```
┌─ UI 线程 ────────────────────────────────┐
│ PlayerBar：250ms 定时器刷进度/按钮态       │
│           40ms 定时器 PumpDueVideoFrame  │
│           Open（Task.Run 解复用+探测）     │
└──────────────────────────────────────────┘
┌─ 解码线程 PreviewDecode（AboveNormal）───┐
│ 循环：Seek请求? → 处理跳转               │
│       EOF?      → 等排空→MediaEnded      │
│       暂停?     → Sleep(20)              │
│       DecodeNext → 音频FeedAudio         │
│                  → 视频EnqueueVideo      │
│ （DecodeNext/Seek 只在此线程串行调用）     │
└──────────────────────────────────────────┘
```

- `IPreviewDecoder` 的 `DecodeNext`/`Seek` **只在解码线程调用**，实现类内部无需加锁。
- 跨线程同步：`volatile` 标志（`_paused`/`_seekRequested`/`_decoderEof`/`_closeRequested`）+ 锁保护数据（`_audioGate` 时钟锚点、`_videoGate` 帧队列）。
- Seek 的实际执行（清缓冲、解码器 seek、复位锚点）**在解码线程上完成**，天然与解码调用互斥。
- `MediaEnded`/`MediaFailed` 在后台线程触发，`PlayerBar` 订阅后用 `Dispatcher.BeginInvoke` 切回 UI 线程。

### 2.3 核心算法

#### 2.3.1 FfmpegDecoder 发送/接收状态机

FFmpeg 新 API 是 push/pull 模型，`DecodeNext` 用状态机把"取一帧"抽象成同步调用（`FfmpegDecoder.DecodeNext`）：

```
while (guard++ < 4096)                     // 保险丝防死循环
  1. receive_frame(音频) → 有帧则 FillAudio 返回   （音频优先，防断音）
  2. receive_frame(视频) → 有帧则 FillVideo 返回
  3. 已全部排空? → return false (EOF)
  4. 上次 send_packet 返回 EAGAIN? → 先重发该包（包未被消费，所有权仍在本类）
  5. 解复用 EOF? → 首次发 null 冲刷包；冲刷后仍无帧则标记排空
  6. av_read_frame 读下一包（读错误按 EOF 处理 → 损坏文件容错）
     - 非目标流（字幕/数据轨）→ unref 跳过
     - send EAGAIN → 挂起包，回到 1
     - send 其它错误 → unref 丢弃，继续（损坏包容错）
```

**容错策略**：解码/解复用错误一律跳过而非失败；`Receive` 连续错误超过 `MaxConsecutiveErrors=32` 才把流标记为排空。损坏文件播到"能播的位置"，不会中途弹错。

#### 2.3.2 音频重采样（FillAudio）

- 惰性初始化：`swr_alloc_set_opts2(&swr, 输出布局, FLT, 采样率, 输入布局, 源格式, 源率)`；输出布局多声道压为 `av_channel_layout_default(2)`。
- 输出样本数上限：`swr_get_delay(内部残留) + 本帧样本数`（`av_rescale_rnd` 向上取整）。
- `frame->extended_data` 是 `byte**`（byte_ptrArray8 结构体）：复制到 `stackalloc byte*[8]` 再传。
- PTS：`best_effort_timestamp × stream->time_base`；缺失时按上一块末尾推算（`_nextAudioPts`）。

#### 2.3.3 视频像素转换（FillVideo）

- `sws_getCachedContext` 转 `AV_PIX_FMT_BGRA`，flags=2（SWS_BILINEAR）；源尺寸/格式变化时重建上下文。
- `frame->data/linesize` 同样复制到固定数组再传（FFmpeg.AutoGen 9 的 `sws_scale` 签名是 `byte*[]/int[]`，生成代码内部 fixed）。
- 视频流选择：手动遍历 `nb_streams`，跳过 `AV_DISPOSITION_ATTACHED_PIC` 封面流；无解码器的轨跳过；`av_find_best_stream` 仅用于音频。

#### 2.3.4 APE 原生解码（ApeDecoder）

P/Invoke `MACDll64.dll`（全部 `__stdcall`）：

| 导出 | 用途 |
|---|---|
| `c_APEDecompress_CreateW(LPWStr, out int)` | 打开文件（`out int` 为错误码，非 0 即损坏） |
| `c_APEDecompress_GetData(h, IntPtr, long, out long)` | 按"块"取 PCM（0=成功） |
| `c_APEDecompress_Seek(h, long block)` | 按块跳转 |
| `c_APEDecompress_GetInfo(h, field, 0, 0)` | 读格式信息 |

- `GetInfo` 字段号：SAMPLE_RATE=1003、BITS=1004、CHANNELS=1006、BLOCK_ALIGN=1007、TOTAL_BLOCKS=1016、LENGTH_MS=1017、FORMAT_FLAGS=1002。
- 每块 16384 样本/声道（约 100~400ms），解码线程数 `clamp(CPU核数/2, 1, 4)`。
- **格式转换算法**：按 FORMAT_FLAGS 标志位（FLOATING_POINT=1<<12、BIG_ENDIAN=1<<9、SIGNED_8BIT=1<<11）分派到 5 条转换路径——16bit/8bit/24bit/32bit 整型、32bit 浮点；24bit 做符号扩展（`v | 0xFF000000`）；大端按字节组装后换算。全部输出 float32。
- DLL 句柄在对象存活期间不能卸载：`NativeLibrary.Load` 的句柄保存到 `_libraryHandle`，`Dispose` 时才 `NativeLibrary.Free`。

#### 2.3.5 播放时钟与 A/V 同步（PreviewPlayerEngine）

- **音频时钟**：解码线程写入每块后更新 `_writtenPtsEnd = Pts + 块时长`；`Position = _writtenPtsEnd − provider.BufferedDuration`（即"已进入输出缓冲但尚未播放"的时间要扣掉）。
- **墙钟**：纯视频（无音频流）用 `Stopwatch` + `_wallClockOffset` 兜底。
- **视频呈现**：UI 按 `Position` 拉取帧——`Pts > now` 留在队列；`now − Pts > 250ms` 视为迟到丢弃并归还缓冲；否则显示。
- **水位控制**：音频缓冲 ≥2s 时解码线程暂停喂数据（Sleep 20ms 轮询，同时响应暂停/跳转/关闭），总缓冲 5s。

#### 2.3.6 缓冲池（PlaybackBufferPool）

- `Rent(minSize)`：找池内"最小够用"的一块复用（避免大缓冲被小块请求长期占用），没有则新分配。
- `Return(buffer)`：池满（默认保留 12 块）则丢弃给 GC。
- 音频块在 `AddSamples`（内部复制）后立即归还；视频帧在 `WritePixels` 完成后归还——解码全程稳态零大数组分配。

## 3. 标签处理

### 3.1 双轨制架构

实测结论（2026-06 沉淀，勿走回头路）：

| 场景 | 工具 | 原因 |
|---|---|---|
| 音频标签**读** | TagLibSharp2 0.6.0 | 各格式原生支持，含 APE/AIFF/DTS |
| 音频标签**写** | TagLibSharp2 0.6.0 | 写后 PCM 采样级一致，不损坏音轨 |
| 视频标签**读** | MediaInfo 26.1.0 | 格式覆盖更稳健 |
| 视频标签**写**、WAV 读写 | TagLib(Sharp) 2.3.0 兜底 | TagLibSharp2 的 WAV RIFF INFO 按 Latin-1 写会中文乱码；MP3/AIFF 音频属性需 TagLib 补读 |

**入口分发**（`TagService.ReadCoreAsync` / `WriteTagsAsync`）：按扩展名 → 音频走 TagLibSharp2Engine，视频走 MediaInfo 读 + TagLib 写。

### 3.2 TagLibSharp2Engine 反射分发机制

`Services/TagLibSharp2Engine.cs`（internal static）：

1. **扩展名映射表**：扩展名 → TagLibSharp2 文件类型全名（如 `.mp3 → TagLibSharp2.Mpeg.AudioFile`、`.ape → TagLibSharp2.Ape.File`）。
2. **反射元数据缓存**：每种文件类型缓存其 `ReadFromFile` 静态方法、`Save` 方法、Tag/Properties 属性的 MethodInfo/PropertyInfo，避免每次调用重复反射查找。
3. **按类型读取**：**必须**分发到 `XxxFile.ReadFromFile(path)`，禁止用 `MediaFile.Read` 工厂嗅探——ID3v2 前缀的 APE 会被误判为 MP3。
4. **封面抽象**：TagLibSharp2 的 `Core.Picture` 是抽象类，引擎自建 `SimplePicture : IPicture`（全格式通用）；两个库的 PictureType 枚举仅名称一致、数值不同，跨库传递时按枚举名映射。
5. **APE 特例**：无标签文件读得的 Tag 可能为 null，写入前必须 `EnsureApeTag()`。

### 3.3 TagService 接口说明

`Services/TagService.cs`（public，实现 `ITagService`）：

```csharp
// 读取
Task<TagData> ReadTagsAsync(string filePath);               // 全量标签
Task<TagData> ReadTagsSummaryAsync(string filePath);        // 摘要（扫描用，跳过重资源）
Task<IReadOnlyList<TagData>> ReadTagsBatchAsync(...);       // 4 路并行批量
Task<CoverArt?> ReadCoverArtAsync(string filePath);         // 按需：选中单文件时才读
Task<string?> ReadLyricsAsync(string filePath);             // 按需

// 写入
Task<bool> WriteTagsAsync(string filePath, TagData tags, bool keepUpdateTime = false);
Task<int> WriteTagsBatchAsync(...);
Task<bool> ClearTagsAsync(string filePath);
Task<bool> WriteCoverArtAsync(string filePath, CoverArt cover);
Task<bool> WriteLyricsAsync(string filePath, string lyrics);
```

- `TagData` 是全格式统一的标签视图（标题/艺术家/专辑/年份/音轨/流派/封面/歌词/音频参数等），屏蔽各格式差异。
- 写入失败返回 false 或批量计数，不抛异常打断批量流程。

### 3.4 批量读取与按需加载策略

- **批量扫描**：4 路并行工作池（实测约 4 倍提速）；大目录扫描/拖拽加载在后台线程执行防界面假死；结果用 `AddRange` 一次批量插入列表。
- **按需加载**：扫描阶段只读文本标签和音频参数（Summary 模式）；封面字节与完整歌词在选中单文件编辑时才加载——全量复制封面会导致大库内存暴涨。
- **目录切换**：释放旧列表全部重资源、清空面板、主动 `GC.Collect` 归还内存。

### 3.5 已知坑与规避方案

| 坑 | 规避 |
|---|---|
| TagLibSharp2 `Core.Picture` 抽象类不可直接 new | 自建 `SimplePicture : IPicture` |
| `BinaryData` 无 `ToArray()` | 用 `.Span.ToArray()` |
| `AudioProperties` 是 struct 不是类 | 用 `is AudioProperties ap` 模式匹配判空 |
| `Tag.Year` 是 string 不是 uint | 写入前转换、读取后按 string 处理 |
| 两库 PictureType 数值不同 | 按枚举**名称**映射 |
| APE 无标签时 Tag 为 null | 写前 `EnsureApeTag()` |
| WAV RIFF INFO 中文乱码（TagLibSharp2 按 Latin-1 写） | WAV 走 TagLib 2.3.0 兜底 |
| ID3v2 前缀 APE 被工厂嗅探误判为 MP3 | 按扩展名分发，禁用 `MediaFile.Read` |

## 4. 编译与发布

```powershell
dotnet build -c Debug     # 0 错误 0 警告
dotnet build -c Release   # 0 错误 0 警告
```

- 目标框架 net10.0-windows，`PlatformTarget=x64`（FFmpeg/MACDll64 仅随 x64 原生二进制分发），`AllowUnsafeBlocks=true`（FFmpeg 指针 API）。
- 关键包：FFmpeg.AutoGen 9.0.1.1、NAudio 3.1.0、TagLibSharp2 0.6.0、TagLibSharp 2.3.0、MediaInfo.Wrapper.Core / MediaInfo.Native 26.1.0、Newtonsoft.Json 13.0.4、System.Data.SQLite.Core 1.0.119。
- MediaInfo.Native 的 Linux RID 资产会触发 NETSDK1206，已在 csproj `NoWarn` 显式忽略（仅分发 win-x64，与运行无关）。
- 发布产物须保留 `ffmpeg\` 与 `mac\` 子目录完整性；缺失时对应功能在打开时报错（`PlaybackException` 本地化提示），不会崩溃。
