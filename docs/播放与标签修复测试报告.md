# 播放与标签修复测试报告

- 测试日期：2026-06-23
- 被测项目：MusicTagRecover（WPF，net10.0-windows，x64）
- 被测配置：Debug、Release
- 构建结果：**0 个警告、0 个错误**（两种配置均通过）

## 一、修复与新增内容概览

| 编号 | 问题/需求 | 涉及文件 |
| --- | --- | --- |
| 1 | 标签读取并行化，提升大目录加载速度 | Services/FileScannerService.cs、Services/TagService.cs |
| 2 | DSF 标签无法修改 | Services/TagLibSharp2Engine.cs |
| 3 | 标签编辑窗口点“保存修改”后界面被清空 | ViewModels/MainViewModel.cs、Views/MainWindow.xaml.cs |
| 4 | 预览/下一曲后需手动再点播放 | Services/Playback/PreviewPlayerEngine.cs |
| 5 | 新增：双击非文件名列自动播放该行 | Views/MainWindow.xaml、Views/MainWindow.xaml.cs |

### 关键根因与修复说明

1. **并行读取**：目录扫描与标签批量读取均改为 4 路并行（`Parallel.ForEachAsync` / `Task.WhenAll` 分组），结果按原始下标归位，保证列表顺序与单线程一致；单文件异常隔离，不中断整批；进度通过 `Interlocked` 上报。
2. **DSF 保存失败**：TagLibSharp2 0.6.0 的 `DsfFile` 只有 `SaveToFile(string, IFileSystem)` 重载，没有旧反射逻辑查找的一参 `SaveToFile(string)`，导致保存被误判失败。保存方法解析改为：优先一参重载，回退两参重载（第二参传 null）。同一回退逻辑也覆盖 DFF 及后续同类格式。
3. **保存后面板清空**：保存后 `ApplyView()` 重建 `Rows`，DataGrid 选区瞬间变空，触发标签面板 `Clear()`。修复为重建期间加守卫、重建后按文件路径恢复选区并重新加载面板数据。
4. **不自动播放**：Open 在线程池执行后立即 Play，此时首块音频尚未进入缓冲，NAudio 读到 0 字节后自动停止输出。改为首块音频入缓冲后由 `EnsureOutputRunning()` 启动输出；解码欠速导致输出停止时也可自动恢复。
5. **双击播放**：DataGrid 双击事件做命中测试，表头/空白区域以及 `filename`（文件名）列直接放行（保留重命名），其余列（艺术家、专辑、标题等）均以该行为起点开始播放整个可见列表。

## 二、测试环境与方法

- Windows + .NET SDK 10.0.401
- 标签库：TagLibSharp（v1，WAV 等常规格式主路径）、TagLibSharp2 0.6.0（DSF/DFF 等格式路径）
- 播放：NAudio 3.1（WaveOut）+ FFmpeg.AutoGen（解码）
- 自动化手段：
  - C# 临时探针直接引用被测工程，做端到端标签/播放/扫描验证；
  - PowerShell + UI Automation（含必要时的物理鼠标点击）驱动真实 WPF 界面。
- 测试媒体均在临时目录生成：3 个 6 秒 WAV（中文标签）、40 个带中文标签的 WAV、以及手工合成的结构合法最小 DSF 文件。

## 三、测试结果

### 1. 标签读取并行化

- 40 个文件扫描数量 40/40：**通过**
- 结果顺序与 `Directory.GetFiles` 枚举顺序一致：**通过**
- 中文标题/艺术家读取正确：**通过**
- 轻量扫描不加载封面字节（避免内存放大）：**通过**
- 时长等音频属性全部填充：**通过**
- 单文件异常被隔离，不影响整批：**通过**
- 热缓存小规模计时：并行约 2ms vs 串行约 7ms（约 3 倍；机械盘/大标签场景收益更高）

### 2. DSF 标签读写（合成最小合法 DSF）

合成样本：DSD chunk 28 字节、fmt chunk 52 字节、data chunk 12 字节头 + 1 个 4096 字节 block，双声道、2822400Hz（DSD64），metadata offset 指向文件尾部。

- 无标签初始读取：**通过**
- 写入中文 Title/Artist/Album/AlbumArtist、Year、Track、TrackCount、Genre、Comment：**通过**
- 回读全部字段逐字段比对：**通过**
- 音频属性 `SR=2822400 Ch=2 Bits=1`：**通过**
- 写入前后音频数据区字节级一致：**通过**
- 对已带 ID3v2 标签的 DSF 二次修改：**通过**
- 清空标签：**通过**
- 探针最终输出 `ALL PASS`

### 3. 保存修改后的界面刷新与落盘

- 选中单个文件，修改标题为中文并点击“保存修改”：编辑面板仍显示更新后的标题，12/12 个编辑框保持可用：**通过**
- 保存后磁盘回读与界面内容完全一致（码点级比对中文标题“界面保存验证”）：**通过**
- 多选两个文件批量保存：两个文件磁盘标签均写入成功，应用不崩溃、列表行数与面板控件保持完整：**通过**
- 附加验证：经引擎直接写入含 U+591A（“多”，UTF-16LE 含 0x1A 控制字节）及裸 0x1A 字符的标题，回读逐字节一致：**通过**

> 测试装置说明：UI Automation 的 `ValuePattern.SetValue` 文本通道会吞掉字符 U+591A 中的 0x1A 字节，导致脚本写入“多”字时磁盘出现 U+0591。该现象仅存在于 UIA 测试通道；真实输入法/键盘编辑与引擎写入路径均验证无损。

### 4. 播放控制

引擎层（无 UI）：

- Open 后立即 Play，位置正常推进（自动播放）：**通过**
- 切换下一曲后自动播放：**通过**
- 自然播放结束触发 MediaEnded：**通过**
- 暂停时钟停止、继续后时钟推进：**通过**
- 全程无 MediaFailed：**通过**

UI 层（3 个 6 秒 WAV）：

- 点击“▶ 预览”后立即出声，时间推进，按钮呈暂停态，无需再点播放：**通过**
- 播放中点击“下一曲”，标题切到下一首（tone2）且自动播放：**通过**
- 自然播完第 1 首（约 6 秒）自动切到第 2 首并继续播放：**通过**
- 快速连点两次“下一曲”：正确落到最后一首并播放，末轨“下一曲”按钮禁用，无错乱：**通过**

> 行为说明：列表单选时“预览”从当前选中行开始播放；无选择时从第 1 行开始。测试初期观察到的“预览后直接到 tone3”即选中行语义（前序用例把选中行留在了第 3 行），非连跳缺陷；中性选择状态下实测 tone1 稳定播放 5.4 秒以上不跳曲。

### 5. 双击播放新功能

- 双击第 2 行标题列（非文件名列）：播放器打开并从 tone2（2/3）开始播放，时间推进：**通过**
- 双击第 3 行文件名列：进入重命名编辑模式且不打开播放器：**通过**
- 表头与空白区域双击无副作用（命中测试直接放行）：**通过**

## 四、已知局限

1. DFF：保存方法回退逻辑理论上同样修复了 DFF（`DffFile` 亦为两参保存重载），但未做端到端样本验证（缺少便于合成的合法 DFF 样本）。
2. DSF 测试基于结构合法的手工合成最小样本，未在真实商业 DSF 唱片文件上验证；读写链路与标签字段映射已完整覆盖。
3. 播放自动下一曲的触发时刻为播放内核读到文件结尾（约 5.8~6.0 秒），与素材标称 6 秒时长一致，属正常行为。

本次 4 项缺陷修复与 1 项新增功能全部通过自动化探针与真实 UI 自动化验证；Debug、Release 两种配置均为 0 警告 0 错误；中文标签（含特殊 Unicode 控制字节场景）经引擎与磁盘回读验证无损。
